# Writing standard

Write community-facing content in clear, inclusive English.
Use exact public symbol names and consistent terminology across guides, examples, configuration, and validation messages.
Prefer active voice, familiar words, sentence-case headings, and descriptive link labels.
Remove filler, unsupported claims, repeated summaries, decorative emphasis, and unexplained jargon.
Keep each sentence clear about who acts and what changes.

Use numbered lists for ordered procedures and bullets for independent items.
State the execution environment and directory before commands.
Put conditions and required configuration before dependent steps.
Show expected output or an observable result after the first runnable example.
Mark optional integrations and prerequisites explicitly.

Follow the owning package's formatter and supported PHP, Laravel, and frontend versions in code examples.
Use synthetic inputs rather than real credentials, customer data, undefined variables, or unexplained application models.
Describe relevant failure behavior and recovery steps where the reader needs them.
Keep preview behavior distinct from released APIs.

For a package README, retain purpose, installation, a minimal example, compatibility or stability, and links to complete documentation and project policies.
Keep configuration reference, architecture, migrations, and troubleshooting in the central documentation.
Use `https://atb.dev.br` for public documentation and `contact@atb.dev.br` for public contact and security reporting.

Review prose after checking technical correctness. Preserve meaning when shortening text.
Prefer a precise sentence over a rigid stylistic rule that makes an instruction harder to understand.

The standard follows [Diataxis](https://diataxis.fr/), [Google's procedures guidance](https://developers.google.com/style/procedures), and [Google's code sample guidance](https://developers.google.com/style/code-samples).
Artisan Toolbox's repository instructions own package-specific requirements and validation commands.
